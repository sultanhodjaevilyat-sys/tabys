# Grill Me — вопросы на защите и ответы

Сначала короткий ответ по-русски, ниже — простая фраза на английском, если защита на английском.

## Часть 1. Что это за проект

**1. Что такое Tabys в двух словах?**
Веб-система для кафе: касса, меню, склад — и модуль «Интеллект», который сам находит, где кафе теряет деньги.
> *Tabys is a web system for cafes. It finds where the cafe loses money.*

**2. Какую проблему решаете?**
iiko, Paloma 365 и Rosta записывают операции, но не говорят владельцу, где потери. У кафе прибыль 5–15 %, поэтому перерасход продуктов и «удаления после пречека» съедают заметную часть прибыли.
> *Other systems only record data. Tabys explains the losses in simple words.*

**3. Чем вы лучше iiko?**
Аудитор потерь, прогноз закупок и AI-ассистент встроены и работают автоматически, а не через отчёты и платных партнёров.

**4. Данные настоящие?**
Нет, тестовые: генератор `backend/app/datagen.py` создаёт 8 недель продаж и специально «подкладывает» две проблемы — перерасход говядины по Вт/Чт и кассира с частыми удалениями. Так видно, что аудитор их находит.
> *The data is generated. We added two hidden problems, and the system finds them.*

## Часть 2. Архитектура и стек

**5. Из чего состоит система?**
Фронтенд (React) → бэкенд (FastAPI) → база (PostgreSQL). Бэкенд ещё ходит в Gemini (AI) и Stripe (оплата). Схема — `docs/ARCHITECTURE.md`.
> *Frontend in React, backend in FastAPI, database PostgreSQL. Backend calls Gemini and Stripe.*

**6. Почему React?** Компоненты переиспользуются (StatCard, Badge, Loader), React Router даёт страницы без перезагрузки, огромное сообщество.

**7. Почему FastAPI, а не Django/Node?** Python удобен для аналитики и AI, FastAPI быстрый, сам делает документацию API на `/docs` и проверяет входные данные через Pydantic.

**8. Почему PostgreSQL?** Надёжная реляционная база, транзакции, внешние ключи. Локально для простоты можно SQLite — код тот же благодаря SQLAlchemy (меняется одна строка `DATABASE_URL`).

**9. Как фронтенд общается с бэкендом?** REST API, JSON. Vite проксирует все запросы `/api/*` на `localhost:8000` (`frontend/vite.config.js`).

**10. Какие есть эндпоинты?**
`GET /api/dashboard`, `/api/menu`, `/api/audit`, `/api/forecast`, `/api/menu-matrix`, `POST /api/agent/chat`, `GET /api/billing/plans`, `POST /api/billing/checkout`, `GET /api/billing/verify`, `POST /api/billing/webhook`. Все видно на http://localhost:8000/docs.

## Часть 3. База данных

**11. Какие таблицы?** `dishes`, `ingredients`, `recipe_items`, `sales`, `stock_usage`, `employees`, `cash_operations`, `subscriptions`.

**12. Где связь многие-ко-многим?** Блюдо ↔ ингредиент через `recipe_items` (это и есть техкарта: сколько граммов ингредиента в порции).
> *Dishes and ingredients are many-to-many through recipe_items.*

**13. Что такое PK и FK?** PK — уникальный номер строки (`id`). FK — ссылка на строку другой таблицы (`sales.dish_id → dishes.id`).

**14. Зачем индексы?** Чтобы быстро искать продажи по дате и блюду (`index=True` на `sold_at`, `dish_id`).

**15. Как заполняется база?** При первом запуске `repo.seed_if_empty()` проверяет, пустая ли таблица блюд, и загружает тестовые данные.

## Часть 4. AI-агент

**16. Это просто чат-бот?** Нет. Это агент с **tool calling**: Gemini получает описание 6 функций и сам решает, какую вызвать (`get_stock_losses`, `get_forecast`, …). Бэкенд выполняет функцию на данных из БД и отдаёт результат модели, а модель пишет ответ. Цифры не выдумываются — они из базы.
> *The AI agent chooses a tool, our backend runs it on real data, then the AI explains the result.*

**17. Где код агента?** `backend/app/agent.py`: `TOOLS` — описание функций, `run_tool` — выполнение, `ask_gemini` — цикл до 5 шагов.

**18. А если нет интернета или ключа?** Включается демо-режим: функция выбирается по ключевым словам, ответ собирается по шаблону. В интерфейсе это честно подписано «демо-режим».

**19. Почему Gemini?** Бесплатный ключ в Google AI Studio, поддерживает function calling.

**20. Как защищён ключ?** Хранится только в `backend/.env`, файл в `.gitignore`, на фронтенд не попадает.

## Часть 5. Оплата (PaySystem)

**21. Как работает оплата?** Stripe Checkout в тестовом режиме: бэкенд создаёт сессию, пользователь платит на странице Stripe тестовой картой `4242 4242 4242 4242`, Stripe присылает webhook — подписка становится `active`.
> *We use Stripe Checkout in test mode. A webhook activates the subscription.*

**22. Зачем webhook, если есть страница «успех»?** Пользователь может закрыть вкладку, а webhook придёт всё равно. Это надёжный источник правды. Дополнительно `/api/billing/verify` сам спрашивает Stripe — на случай, если webhook не дошёл (локально без Stripe CLI).

**23. Как защитились от подделки webhook?** Подпись проверяется `stripe.Webhook.construct_event` с секретом `STRIPE_WEBHOOK_SECRET`.

**24. Что будет при повторном webhook?** Ничего плохого: статус просто остаётся `active` (идемпотентность).

**25. Почему не Kaspi?** API Kaspi Pay дают только ИП/ТОО по договору. Stripe даёт тестовый режим любому. Архитектура та же — шлюз можно заменить в одном файле `billing.py`.

## Часть 6. Модуль «Интеллект» (формулы)

**26. Как работает аудитор склада?** Ожидаемый расход = продажи × норма по техкарте. Перерасход = факт − ожидаемый. Если больше 5 % — сигнал. Потеря в ₸ = перерасход × цена.

**27. Аудитор кассы?** Считаем удаления после пречека на 100 чеков у каждого кассира. Если в 2+ раза чаще коллег — сигнал.

**28. Прогноз?** Среднее продаж в такой же день недели за 4 недели × тренд (последние 2 недели / предыдущие 2, ограничен 0,8–1,2).

**29. Автозаказ?** Прогноз × техкарта × 1,15 (страховой запас 15 %) − остаток на складе.

**30. Матрица меню?** Метод Касаваны–Смита: популярность ≥ 70 % от средней доли, маржа ≥ средневзвешенной. Звезда / Лошадка / Загадка / Собака.

**31. Как проверили, что формулы верные?** 19 автотестов (11 на формулы + 8 на API), они же запускаются в GitHub Actions при каждом PR: `cd backend && python -m unittest -v`. Есть тест с ручным примером: 10 продаж × 0,2 кг = 2 кг, факт 2,5 кг → +25 %, потеря 500 ₸.

**31а. А в браузере проверяли?** Да — e2e-тест `e2e/smoke.mjs` (Playwright) в GitHub Actions поднимает бэкенд и сайт, открывает все 9 страниц в Chromium, крутит 3D-модель мышкой, задаёт вопрос агенту и проходит оплату. Тест падает, если на странице есть ошибка JavaScript.
> *We have end-to-end tests: a real browser opens every page in CI.*

**31б. Тесты нашли реальную ошибку?** Да. В чате эффект React был записан как `useEffect(() => el.scrollIntoView(...))` — без фигурных скобок он *возвращает* результат. В новых браузерах `scrollIntoView()` возвращает Promise, React принимал его за функцию очистки и падал «n is not a function» при каждом новом сообщении. e2e-тест это поймал, исправили одной строкой (см. коммит `fix(assistant)` в PR #1).
> *The e2e test found a real bug in the chat, and we fixed it.*

## Часть 7. Фронтенд и 3D

**32. Сколько страниц?** 9 + 404: Главная, Панель, Меню, Склад, Аудитор, Матрица, AI-ассистент, Тарифы, Успешная оплата.

**33. Как сделана 3D-модель?** three.js: моноблок, принтер чеков, терминал, денежный ящик собраны из 3D-фигур. Экран моноблока — текстура, нарисованная на canvas. `OrbitControls` даёт вращение мышкой и автоповорот. Код: `frontend/src/components/PosModel3D.jsx`.

**34. Зачем она по смыслу?** Показывает рабочее место кассира, которое автоматизирует Tabys, а на экране — реальные цифры аудитора.

**35. Адаптивность?** Брейкпоинты 1100 / 960 / 640 px, бургер-меню на телефоне. В Figma есть мобильные экраны 390 px.

## Часть 9. Что добавили после проверки (PR #4, #6, #7)

**39. Агент умеет только сводки?** Нет. Седьмой инструмент `get_dish_info(dish_name)` — с параметром: Gemini сам достаёт название блюда из вопроса («Расскажи про лагман»), бэкенд находит блюдо и отдаёт техкарту, себестоимость, маржу, продажи за неделю и место в матрице меню.
> *The agent can call a tool with a parameter: the dish name.*

**40. Как запустить весь проект одной командой?** `docker compose up --build` — поднимаются три контейнера: PostgreSQL 16, FastAPI и nginx с собранным React. Сайт: http://localhost:8080. nginx отдаёт страницы и пересылает `/api` на бэкенд.
> *One command starts the database, the backend and the website.*

**41. Почему цифры выглядят по-русски?** Агент и сайт пишут дробные числа с запятой (`12,5 кг`), даты как `26.11.2026` и склоняют слова: «1 чек, 2 чека, 5 чеков». Это проверено автотестами.
> *Numbers, dates and word endings follow Russian rules.*

**42. Что проверяет CI сейчас?** 4 задачи: 24 теста бэкенда на Python 3.10 и 3.12, сборка фронтенда, e2e в Chromium по всем страницам и запуск docker compose с проверкой сайта и API на настоящем PostgreSQL.
> *Every pull request is tested automatically in four jobs.*

**43. Почему дизайн именно такой? Для кого он?** Наши пользователи — владельцы кафе 35–40+. После 40 почти у всех начинается пресбиопия, мелкий и бледный текст читать тяжело. Поэтому шрифт 17 px, контраст по стандарту WCAG AA, кнопки 44–48 px, без капса и сокращений. Подробно с источниками: `docs/UX_RATIONALE.md`.
> *Our users are 40 plus, so we made the text bigger and the contrast higher.*

**44. Почему зелёный и золотой?** Зелёный связывают с деньгами и ростом, а «табыс» значит «прибыль». Золотой — акцент, только как фон под тёмным текстом. Красный — только для потерь, и всегда вместе со значком ⚠, потому что около 8 % мужчин плохо различают красный и зелёный. Контраст всех пар проверен: от 4,6 до 15,3 к 1.
> *Green means money and growth. Red is only for losses, always with an icon.*

**45. Чем вы лучше iiko?** iiko мощная, но в отзывах пишут, что половиной функций не пользуются. Мы не соревнуемся количеством функций: Tabys работает поверх кассы и показывает только то, что влияет на прибыль, простыми словами.
> *We do not replace the cash register. We show where the money is lost.*

# Что, где и как добавлять

| Хочу добавить… | Где | Как |
|---|---|---|
| **Новую страницу** | `frontend/src/pages/Новая.jsx` | Создать компонент → добавить `<Route path="novaya" …>` в `App.jsx` → ссылку в массив `links` в `components/Layout.jsx` |
| **Новый API-эндпоинт** | `backend/app/main.py` | `@app.get("/api/...")` + функция; данные брать через `data(db)` |
| **Новую формулу аналитики** | `backend/app/analytics.py` | Чистая функция над списками → тест в `backend/tests/test_analytics.py` |
| **Новый инструмент AI-агенту** | `backend/app/agent.py` | 1) описание в `TOOLS` (name, description, parameters) 2) ветка в `run_tool` 3) (необязательно) ключевые слова в `KEYWORDS` для демо-режима |
| **Новый тариф** | `backend/app/billing.py` | Добавить запись в `PLANS` — страница тарифов подхватит сама |
| **Новое блюдо / продукт** | `backend/app/datagen.py` | Добавить в `DISHES` / `INGREDIENTS` и техкарту в `RECIPES`, удалить `tabys.db`, перезапустить бэкенд |
| **Новый инструмент AI-агенту** | `backend/app/agent.py` | Описание в `TOOLS` (имя, параметры), ветка в `run_tool`, ключевые слова в `KEYWORDS` для демо-режима |
| **Запуск в Docker** | `docker-compose.yml` | `docker compose up --build` → http://localhost:8080; ключи из `backend/.env` |
| **Новую таблицу в БД** | `backend/app/models.py` | Класс-модель SQLAlchemy; таблица создастся при старте (`create_all`) |
| **Ключ Gemini / Stripe** | `backend/.env` | `GEMINI_API_KEY=...`, `STRIPE_SECRET_KEY=sk_test_...`, перезапустить uvicorn |
| **PostgreSQL** | `backend/.env` | `docker compose up db` и `DATABASE_URL=postgresql+psycopg2://tabys:tabys@localhost:5432/tabys` |
| **Webhook локально** | терминал | `stripe listen --forward-to localhost:8000/api/billing/webhook`, секрет `whsec_...` → `STRIPE_WEBHOOK_SECRET` |
| **Новую деталь в 3D** | `frontend/src/components/PosModel3D.jsx` | В `buildModel()` создать `new THREE.Mesh(геометрия, материал)` и `root.add(...)` |
| **Цвет / стиль** | `frontend/src/styles.css` | Переменные в `:root` (`--green`, `--gold` …) — те же, что в Figma |

## Если что-то сломалось на защите

- **Сайт пишет «Ошибка… бэкенд запущен?»** → не запущен uvicorn (терминал 1).
- **Чат отвечает «демо-режим»** → нет `GEMINI_API_KEY` в `.env` — это нормально, так и объяснить.
- **Оплата сразу «успешна» без Stripe** → нет `STRIPE_SECRET_KEY`, работает демо-режим оплаты.
- **Данные странные после изменений** → удалить `backend/tabys.db` и перезапустить.
